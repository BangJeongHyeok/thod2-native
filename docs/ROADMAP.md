# 로드맵

프로젝트 개요와 실행 파일 분석 결과는 [../AGENTS.md](../AGENTS.md)를 본다.
이 문서는 전체 방향과 단계를 정한다. 도메인별 세부 목표와 진행 기록은 [work/README.md](work/README.md)의 작업 문서에서 관리한다.

## 비전

**The House of the Dead 2 PC판의 오픈 소스 재구현(소스 포트)** 을 만든다.
참고 모델은 OpenRCT2(롤러코스터 타이쿤 2)와 RVGL(Re-Volt)이다.

- 플레이어는 자기가 가진 원본 게임 데이터만 있으면 현대 PC에서 바로 실행할 수 있다.
- 다른 개발자가 코드와 문서를 보고 모드나 새 기능을 쉽게 추가할 수 있다.
- 고해상도, 와이드스크린, 고프레임은 **따로 핵을 만드는 게 아니라**, 렌더러와 타이밍을 현대적으로 재구현한 결과로 자연스럽게 얻는다.

## 우선순위

1. **현대 PC에서 잘 동작하게 만들기** (최우선)
2. **확장성 높은 구조로 재구성하기** (하이브리드 재구현 + 모드 API)
3. 그 결과로 얻는 현대화 기능 (고해상도, 와이드스크린, 고프레임 등)
4. 외부 개발자가 참여할 수 있는 오픈 소스 프로젝트로 다듬기

## 기본 원칙

- **점진적 재구현 (OpenRCT2 방식).** 한 번에 다시 만들지 않는다. 원본 `Hod2.exe`에 우리 DLL을 주입하고, 원본 함수를 하나씩 우리 코드로 교체한다. 어느 시점에서든 게임은 **항상 처음부터 끝까지 플레이 가능한 상태**를 유지한다.
- **원본 동작 일치.** 교체한 함수는 원본과 결과가 같은지 확인한 뒤에 "검증됨"으로 표시한다. 버그 수정이나 동작 변경은 일치 확인 후 별도 옵션으로 넣는다.
- **원본 자산과 원본 코드는 배포하지 않는다.** 저장소에는 우리가 작성한 코드, 문서, 도구만 둔다. 실행할 때는 사용자의 원본 데이터 폴더를 읽는다.
- **문서 우선.** 분석한 함수, 구조체, 파일 포맷은 코드보다 먼저 문서로 남긴다. 다른 개발자가 참여할 수 있는 핵심 자산이다.

## 하지 않는 것

- 처음부터 전부 다시 쓰는 빅뱅 재작성
- 원본 게임 파일이나 디컴파일한 원본 코드를 그대로 저장소에 넣는 것
- 수정된(크랙된) 실행 파일에 의존하는 것. 필요한 패치는 우리 코드가 실행 시점에 적용한다.

## 1단계 — 현대 PC 호환 (최우선)

**목표:** 깨끗한 Windows 10/11에서 DxWnd, 호환성 플래그, 관리자 권한 없이 더블클릭으로 실행되고 끝까지 플레이할 수 있다.

### 1-1. 현황 조사
- [x] 테스트용 게임 사본에서 아무 도구 없이 실행하고 문제를 기록한다 ([work/compat-survey.md](work/compat-survey.md)).
- [ ] 확인할 항목: 화면 모드 전환, 창 모드, Alt+Tab, 고주사율 모니터에서 게임 속도, DPI 배율, 다중 모니터, 마우스 조준, 사운드, 세이브 파일 위치, CD 확인 (고주사율, DPI, 세이브 위치 남음)
- [ ] 비교용으로 기존 래퍼(dgVoodoo2, DDrawCompat)를 적용한 결과도 기록한다 (사용자 확인 후 다운로드). dgVoodoo2 완료, DDrawCompat 보류

### 1-2. 런처와 로더
- [ ] ~~`thod2.exe` 런처: 게임 데이터 경로를 찾고, 원본 실행 파일을 실행하면서 우리 DLL을 주입한다.~~ → 프록시 방식으로 결정해서 보류
- [x] 또는 프록시 DLL 방식(`dinput.dll` 등)으로 로드한다. 둘 중 하나로 정하고 이유를 문서로 남긴다. → **`dinput.dll` 프록시로 결정** ([work/loader.md](work/loader.md))
- [ ] MinHook 기반 후킹 도우미와 고정 주소 패치 도우미 (IAT 후킹 도우미 완료, 코드 후킹·고정 주소 패치는 필요할 때)

### 1-3. 호환성 수정
- [ ] **렌더링:** DX7이 현대 드라이버에서 안정적으로 동작하게 한다. 초기에는 검증된 래퍼를 써도 되지만, 최종적으로는 2단계의 자체 렌더러로 대체한다. → **1단계는 dgVoodoo2로 처리하기로 결정** ([work/platform-display.md](work/platform-display.md))
- [ ] **화면:** 테두리 없는 창 모드, 데스크톱 해상도와 무관한 렌더링, DPI 인식 → 테두리 없는 창·Alt+Enter는 dgVoodoo2로 처리, 설치 안내 [INSTALL.md](INSTALL.md) (DPI 인식은 미확인)
- [ ] **타이밍:** 모니터 주사율과 관계없이 게임 로직이 원본 속도(60Hz로 추정)로 돈다. → CPU 100%(바쁜 대기)는 `frame_wait_sleep`으로 해결. 게임 속도는 고정 60fps 타이머로 정해지는 것으로 보임, 240Hz 모니터에서 빨라지지 않음을 확인 ([work/platform-timing.md](work/platform-timing.md))
- [ ] **입력:** 현대 마우스(Raw Input), 게임패드 대응
- [ ] **CD 확인:** 원본 실행 파일 수정 없이 우리 코드에서 처리 → **나중으로 미룸** (2026-10-15 사용자 결정. 보유한 실행 파일은 CD 확인이 이미 지워져 있어 지금 막히는 것이 없음. 1단계 완료 기준에 넣지 않음, [work/platform-filesystem.md](work/platform-filesystem.md))
- [x] **파일 경로:** 세이브와 설정을 게임 폴더 대신 사용자 폴더(`%APPDATA%` 등)에 저장해서 관리자 권한이 필요 없게 한다. → `redirect_user_files`로 세이브·캐시·크래시 로그를 사용자 폴더로 ([work/platform-filesystem.md](work/platform-filesystem.md))

**완료 기준:** 깨끗한 Windows 11에서 런처를 실행하면 테두리 없는 창으로 시작하고, 144Hz 모니터에서도 원본 속도로 처음부터 끝까지 플레이된다.

## 2단계 — 확장 가능한 구조 (하이브리드 재구현)

**목표:** 원본 코드를 서브시스템 단위로 우리 코드로 바꿔 가면서, 각 서브시스템에 명확한 인터페이스와 모드 확장 지점을 만든다.

### 2-1. 리버싱 인프라
- [ ] Ghidra로 분석한 결과(함수 이름, 주소, 시그니처, 구조체)를 **텍스트로 내보내서** `re/`에 저장한다. 원본 코드를 포함하는 Ghidra 프로젝트 파일은 커밋하지 않는다. → 함수·전역 변수·코드 위치는 완료 (`re/*.csv`, `tools/re/sync.ps1 -Export`). 구조체는 아직
- [x] 분석 결과를 Ghidra에 다시 적용하는 스크립트를 만들어서, 여러 사람이 같은 이름으로 작업할 수 있게 한다. → `tools/re/sync.ps1 -Apply` / `-Import` ([re/README.md](../re/README.md))
- [x] 리버싱 규모 산정과 가능성 판정 → 함수 약 2,881개 중 리버싱 대상 2,213개, M1~M3 약 3–6인월(숙련자 기준 가정) ([work/reverse-engineering.md](work/reverse-engineering.md) "리버싱 규모 산정")
- [x] 함수 진행 상태 목록 (`re/functions.csv`): 미확인 → 이름 붙임 → 재구현됨 → 검증됨 (`unnamed` → `named` → `implemented` → `verified`)

### 2-2. 플랫폼 계층
OS와 하드웨어에 닿는 부분을 먼저 교체한다. 원본 게임 로직과 가장 덜 얽혀 있고, 1단계 호환성 문제를 근본적으로 해결한다.
- [ ] 창과 메시지 루프
- [ ] 타이밍과 메인 루프 (로직 업데이트와 렌더링 분리의 기반)
- [ ] 입력 (DirectInput → 자체 입력 계층) → 매 프레임 입력 갱신(`0x41E120`)과 키보드·마우스·조이스틱 읽기 재구현, 원본과 10,800프레임 일치 확인. 기본값은 아직 원본 ([work/platform-input.md](work/platform-input.md))
- [ ] 오디오 (DirectSound → 현대 오디오 API)
- [ ] 파일 입출력 (데이터 경로 추상화, 덮어쓰기 폴더 지원의 기반)

### 2-3. 렌더러
- [ ] DX7 API 수준이 아니라 **게임의 그리기 함수 수준**에서 가로채서 자체 렌더 인터페이스로 넘긴다.
- [ ] 렌더 백엔드는 인터페이스 뒤에 둔다 (1차: D3D11. 이후 Vulkan/OpenGL 가능).
- [ ] 이 단계가 끝나면 임의 해상도, 와이드스크린, 안티에일리어싱이 렌더러 옵션이 된다.

### 2단계 마일스톤
| 마일스톤 | 내용 |
|---|---|
| M1 | 플랫폼 계층 교체 완료: DirectInput과 DirectSound를 원본이 직접 쓰지 않는다 |
| M2 | 렌더러 교체 완료: DX7을 쓰지 않는다 |
| M3 | 모든 자산을 우리 로더로 읽는다. 덮어쓰기 폴더가 동작한다 |
| M4 | **독립 실행:** `Hod2.exe` 코드 없이 우리 실행 파일과 원본 데이터만으로 실행된다. 이때부터 x64 빌드가 가능하다 |

M4는 장기 목표다. M1~M3만으로도 현대화 기능과 모드 개발 대부분이 가능하다.

## 3단계 — 현대화 기능 (2단계의 결과로 얻는 것)

| 기능 | 기반 |
|---|---|
| 고해상도, 임의 해상도 | 2-3 렌더러 |
| 와이드스크린 + HUD 배치 | 2-3 렌더러 + HUD 그리기 재구현 |
| 고프레임 (로직 60Hz + 렌더 보간) | 2-2 메인 루프 분리 + 2-5 로직 상태 정리 |
| 고해상도 텍스처 교체 | 2-4 자산 계층 |
| 현대 라이트건 (Sinden, GUN4IR 등) | 2-2 입력 계층 |
| 설정 UI, 게임 내 오버레이 | 2-3 렌더러 + 2-6 모드 API |

**고프레임 관련 위험:** 원본 로직과 렌더링이 한 함수 안에 섞여 있으면 보간 작업량이 커진다. 이 경우 카메라 보간을 먼저 내고, 오브젝트와 애니메이션 보간은 2-5 진행에 맞춰 넓혀 간다.

## 참고 프로젝트

- **OpenRCT2:** 처음에는 원본 RCT2 실행 파일에 DLL을 주입해서 함수를 하나씩 재구현했고, 결국 원본 코드 없이 독립 실행되는 단계까지 갔다. 이 프로젝트의 진행 방식(2단계)의 모델이다.
- **RVGL:** Re-Volt를 현대 PC용으로 다시 만든 포트. 원본 데이터 위에 커뮤니티가 만든 차량과 트랙을 폴더 단위로 얹는 구조가 2-4 자산 덮어쓰기와 2-6 모드 API의 참고가 된다.
- **Flycast:** 드림캐스트/NAOMI 에뮬레이터. 원작 동작과 화면을 비교하는 기준으로 쓴다.
