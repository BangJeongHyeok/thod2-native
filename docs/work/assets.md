# 자산(리소스)

- **상태:** 진행 중
- **관련 로드맵:** ROADMAP 2-4
- **관련 코드:** `src/assets/`, `tools/assets/`, `docs/formats/`
- **마지막 갱신:** 2026-10-26

## 주요 목표

게임 데이터 파일(`pol`, `tex`, `mot`, `cam`, `coli`, `evt`의 `.bin`, `sound`의 `.wav`) 포맷을 분석해서 문서화하고, 우리 로더로 읽는다. 같은 경로의 파일을 `data/`나 `mods/<이름>/data/`에 두면 원본 대신 로드하는 데이터 덮어쓰기 기능(RVGL 방식)을 제공한다. 추출·변환 도구를 만든다.

**완료 기준:** 모든 자산을 우리 로더로 읽고, 각 포맷이 `docs/formats/`에 문서화되어 있으며, 텍스처 하나를 교체하는 예제 모드가 동작한다.

## 미해결 질문

- 같은 텍스처 번호를 다른 팔레트로 만드는 경우가 있는지 (있다면 교체 파일 이름에 팔레트를 넣어야 함)
- `0x41CCE0`의 다른 뱅크 읽기 경로가 무엇인지
- `tex/scr_blood_*.bin` 피 색상 교체가 어떤 원리인지 (`scr_blood_red`는 뱅크 `0x1BA`, `scr_blood_green`은 `0x1BB`로 따로 있다)
- 구출 결과 화면 배경과 타이틀 로고 5조각(`1390`~`1393`, 따로 업스케일)이 게임 화면에서 이음매 없이 보이는지
- 3D 모델 텍스처(`LoadModelTextures` 경로)도 같은 방식으로 바뀌는지 (훅은 걸려 있지만 시험하지 않음)
- 2048보다 큰 이미지를 넣으면 `ClampTextureSize`가 줄이는지, 실패하는지

- **계기:** 사용자 질문. Options, Network 같은 아웃게임 화면에도 업스케일이 다 들어갔는지.

  - 데모에서 교체 없이 만들어진 텍스처는 `scr_` 밖의 뱅크뿐이었다: `st1_03b`, `st1_03`, `st1_1`, `tutorial`(3D 무대), `common`, `etc_komono_gal`.

  - `etc_komono_gal.bin`은 `tex_extract.py`로 풀다가 LZSS 범위 오류가 났다. 압축 방식이 다른지 확인이 필요하다.
- **다음:** 화면이 켜진 상태에서 메뉴별 진입을 다시 돌려 아웃게임 화면이 쓰는 뱅크를 확인한다. `common.bin`의 UI 글자도 업스케일 대상에 넣을지 정한다.

### 2026-10-28 — 타이틀 메뉴 글자 업스케일 (G1-7)

- **찾은 것:**
  - 타이틀 메뉴(`Network`/`Arcade mode`/`Original mode` …)는 2D 스프라이트가 아니라 **3D 원통 모델**에 붙은 텍스처다.
  - 텍스처는 `komono_title.bin`(뱅크 `0x73`)의 7개다: `DF3` Arcade mode, `DF4` Original mode, `DF5` Training mode, `DF6` Boss mode, `DF7` Rankings, `DF8` Options, `DFF` Network. 모두 0x902 배치(직사각형 ARGB4444)다.
  - `scr_title`에 같은 글자가 다른 번호(`DF9`~`DFE`)로 따로 있다. 그래서 이전에 `DF9`를 바꿔도 메뉴가 그대로였다.
  - `scr_*`가 아닌 뱅크는 326개다. 메뉴용으로 보이는 것은 `komono_title`뿐이다.
- **한 일:**
  - `upscale-ui.ps1`에 `$BankGroups`를 넣었다. 여러 뱅크를 같은 묶음 그림에 넣어 한 번에 업스케일하고, 결과는 뱅크별 폴더에 쓴다. `komono_title`을 `scr_title`과 묶었다 (사용자 요청: 한 화면의 텍스처는 한 번의 업스케일로 일관성 유지).
  - 추출 대상에 `komono_title.bin`을 더했다. 전체 3,025개다.
- **결과:**
  - `scr_title`과 `komono_title`의 글자가 같은 묶음 그림 한 장(`scr_title_0`)에 들어갔다. 자동 검증에서 크기 오류 0개, 빠진 것 0개.
  - 게임 로그에 `DF3`~`DF8`, `DFF`가 4배로 교체되었다. 뱅크 폴더(`data\tex\komono_title\`)에서 찾았다. 모델 텍스처 경로도 항목 표 주소로 뱅크를 알 수 있다.
  - 메뉴 글자의 계단 현상이 줄었다 (`screenshots\menu_compare2.png`).
- **4:3을 넘는 부분:**
  - 타이틀 로고 오른쪽 조각(`1393`)은 x = 548~676으로 4:3 밖까지 나간다. 와이드스크린에서는 넓어진 화면 안이라 잘리지 않는다.
  - 메뉴 배경은 화면 비율별로 거울 채우기를 확인했다.

    | 화면 비율 | 넓힘 배수 | 뒤집어 그린 조각 (로그 줄 수) | 빈 곳 |
    |---|---|---|---|
    | 16:9 | 1.333 | 32 | 없음 |
    | 21:9 | 1.750 | 60 (끝에서 2번째 줄까지) | 없음 |
    | 32:9 | 2.667 | 152 (그림 전체가 양쪽에 한 번씩) | 없음 |
  - 32:9에서는 거울 그림이라 달이 세 번 보인다.
  - 첫 타이틀 화면은 배경이 3D라 Hor+로 넓게 보인다.

### 2026-10-26 — 구출 결과 화면 배경 배치 (G1-10)

- **계기:** 사용자가 구출 결과 화면을 바로 볼 방법(치트, 화면 직접 띄우기)이 있는지 물었다.
- **한 일:**
  - `scr_result` 텍스처 `11F1`~`1201`을 쓰는 스프라이트를 찾았다. `g_spriteTextures`에서 `0xA2A`~`0xA3A`다.
  - 이 스프라이트를 그리는 코드는 `0x434AB0` 하나다. `DrawSpriteAt`(`0x41C7A0`)으로 그리고, 깊이 값은 1.1, 배율은 1이다.
  - 배치: 128px 격자, 5칸 × 4줄. 2번째 줄은 x = 128~384(사진 창 자리)를 건너뛴다. 그래서 17조각이고, 그림 크기는 640×512다.
  - 이 배치를 `upscale-ui.ps1`의 `$KnownLayouts`에 넣었다. 결과 화면 배경도 원래 그림으로 맞춰 붙여서 사진 모델로 업스케일한다.
  - `0x4354F0`은 이 화면용으로 뱅크 `0x16A`를 읽는다.
- **거울 조건:** 왼쪽 끝 줄(x = 0)과 오른쪽 끝 줄(x = 512~640)이 4:3 끝에 정확히 닿는다. 그래서 `widescreen_mirror` 조건에 양쪽 모두 맞는다.
- **미리보기:** 이 배치와 와이드스크린 계산(16:9, x를 320 기준으로 1/1.333 좁히기, 끝 줄 뒤집기)으로 배경만 다시 그렸다 (`screenshots\result_preview.png`). 양옆이 돌벽으로 채워지고, 업스케일 쪽은 조각 경계선이 없다. 사진 창과 글자는 들어 있지 않다.
