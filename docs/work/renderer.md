# 렌더러

- **상태:** 진행 중 (자체 렌더러 전까지 dgVoodoo2 설정 관리)
- **관련 로드맵:** ROADMAP 1-3, 2-3
- **관련 코드:** `src/renderer/` (예정), `config/dgvoodoo-recommended.ini`, `tools/compat/quality-compare.ps1`
- **마지막 갱신:** 2026-10-15

## 주요 목표

DX7(DirectDraw7 + Direct3D7)을 쓰지 않는 자체 렌더러를 만든다. DX7 API 수준이 아니라 게임의 그리기 함수 수준에서 가로채서 렌더 인터페이스로 넘기고, 백엔드는 인터페이스 뒤에 둔다 (1차: D3D11). 이 결과로 임의 해상도, 와이드스크린, 안티에일리어싱, 고프레임 보간 렌더링을 지원한다. 초기 호환성 확보용으로 기존 래퍼를 임시로 쓸 수 있다.

**완료 기준:** 원본이 DX7을 전혀 쓰지 않고, 원본과 같은 화면이 나오며, 해상도와 화면 비율을 자유롭게 설정할 수 있다.

## 중목표 / 소목표

- [x] G1-1 안티에일리어싱(MSAA 4x/8x), 이방성 필터링(16x), 밉맵 자동 생성 비교
- [x] G1-2 성능(GPU 사용률, 초당 프레임, 프레임 간격) 비교
- [x] G1-3 권장 프리셋에 반영할 값 결정 (사용자 결정)

### G2. 자체 렌더러 — 대기

## dgVoodoo2 화질 옵션 비교 (2026-10-15)

`tools/compat/quality-compare.ps1`: 설정마다 dgVoodoo2를 다시 설치하고 권장 프리셋 위에 옵션을 더해 실행한다. 게임이 타이틀 카메라(`cam\cp_title.bin`)를 읽은 시각부터 1.5초(타이틀)와 9.5초(데모) 뒤 화면을 캡처한다. 게임이 고정 60fps 타이머로 돌기 때문에 이 기준이면 실행마다 같은 장면이 찍힌다. 테스트 PC: RTX 3080, 주 모니터 1920×1080 240Hz, 렌더 1440×1080.

| 설정 (권장 프리셋에 더한 값) | GPU 3D 사용률 | 초당 Flip | 결과 |
|---|---|---|---|
| 없음 (권장 프리셋) | 약 5% | 60 | 폴리곤 테두리(지붕선, 좀비 어깨)에 계단이 보인다. 텍스처는 각진 픽셀 (원본이 point sampling으로 그림) |
| `Antialiasing = 4x` | 약 9% | 60 | **테두리 계단이 대부분 매끄러워진다.** 텍스처는 그대로 |
| `Antialiasing = 8x` | 약 13% | 60 | 4x보다 약간 더 매끄럽다. 2배 확대해야 겨우 보이는 차이 |
| `Filtering = 16` (이방성 16x) | 약 5% | 60 | 텍스처가 부드럽게 바뀐다 (덩굴·나뭇잎·벽돌의 각진 픽셀이 사라짐). 테두리 계단은 그대로. **원본 분위기가 달라진다** |
| `Antialiasing = 8x`, `Filtering = 16`, `Mipmapping = autogen_bilinear` | 약 14% | 60 | 위 둘을 합친 모습 |

- 모든 설정에서 프레임 간격 평균 16.66~16.67ms로 변화 없음.
- 비교 이미지는 저장소 밖 `E:\Repos\hod2-native\screenshots\`에 있다 (게임 화면이라 저장소에 넣지 않음).
- 시험 중 겪은 문제와 해결:
  - 실행 시작 시각 기준으로 캡처하면 로딩 시간 차이로 장면이 어긋난다 → 타이틀 카메라 읽기 시각 기준으로 바꿈.
  - 이전 실행의 로그가 남아 있으면 타이틀 카메라를 이미 읽은 것으로 잘못 판단한다 → 실행 전에 로그 삭제.
  - 게임이 남아 있으면 dgVoodoo2 DLL을 바꾸지 못해 설정이 적용되지 않는다 → 설정을 바꾸기 전에 게임을 종료하고 기다리며, 실패하면 측정을 멈춤.

## 결정 사항

| 날짜 | 결정 | 이유 / 대안 |
|---|---|---|
| 2026-10-15 | **권장 프리셋에 `Antialiasing = 4x` 추가** (사용자 결정) | 4x만으로 테두리 계단이 충분히 줄고, 8x와의 차이는 작다. 다른 사람의 약한 그래픽 카드도 고려. 8x는 원하는 사람이 바꾸도록 [INSTALL.md](../INSTALL.md)에 안내 |
| 2026-10-15 | **텍스처 필터링은 원본 그대로(`appdriven`)** (사용자 결정) | 강제 필터링은 화질 개선이라기보다 원본의 각진 픽셀 느낌을 부드럽게 바꾸는 것. 원하는 사람만 켜도록 안내 |

## 작업 기록

### 2026-10-15 — dgVoodoo2 화질 옵션 비교와 권장 프리셋 반영 (관련: G1)

- **한 일:** `tools/compat/quality-compare.ps1`을 만들어 MSAA 4x/8x, 이방성 16x, 조합을 비교했다. 같은 장면을 잘라 확대한 비교 이미지를 사용자에게 보여 주고 결정을 받았다. 권장 프리셋 `config/dgvoodoo-recommended.ini`에 `Antialiasing = 4x`를 넣고 테스트 사본에 적용했다.
- **결과:** 위 "dgVoodoo2 화질 옵션 비교"와 결정 사항.
- **다음:** 화질에서 더 나아가려면(와이드스크린, HUD, 고해상도 텍스처) 자체 렌더러나 게임 코드 분석이 필요하다.

### 2026-10-14 — 화면 처리 방식 결정 (화면 모드 분석에서 넘어온 내용)

- **결과:** 자체 렌더러를 만들기 전까지 창 모드, Alt+Enter, 고해상도는 dgVoodoo2(DX7 → D3D11 래퍼)로 처리하기로 했다 (사용자 결정, B안). 이 도메인의 "초기 호환성 확보용 기존 래퍼"가 확정된 것이다. 창 모드 직접 구현은 자체 렌더러의 요구 사항이 된다.
- **상세:** [platform-display.md](platform-display.md) "결정 사항"

### 2026-10-14 — 화면 모드 분석에서 넘어온 내용

- **결과:**
  - 렌더 구성: `SetDisplayMode(640, 480, 16bpp)`, primary 플립 체인(백버퍼 1장, `3DDEVICE`), 16비트 Z 버퍼 640×480, 16비트 텍스처 약 700개(일부 알파 포함). 매 프레임 `Flip(DDFLIP_WAIT)`.
  - Direct3D는 `IDirectDraw7::QueryInterface(IID_IDirect3D7)`로 얻는다 (호출 위치 `0x4BD2F3`).
  - Windows 호환 모드(`DWM8And16BitMitigation`, `apphelp.dll`)가 DirectDraw 함수 표를 덮어쓴다. DX7 수준에서 후킹하는 코드는 이것을 고려해야 한다.
- **상세:** [platform-display.md](platform-display.md) "화면 모드 분석 결과"

### 2026-10-14 — 호환성 조사에서 넘어온 내용

- **결과:**
  - Windows 11은 DX7을 `DDRAW.dll` → `D3DIM700.DLL` → `dxgi.dll` + 그래픽 드라이버 순서로 처리한다.
  - dgVoodoo2 v2.87.5(DX7 → D3D11 래퍼)를 게임 폴더에 넣으면 원본 수정 없이 **테두리 없는 창 + 1440×1080(4:3) 렌더링**이 가능하다. 3D와 HUD 모두 선명해진다. 1단계의 임시 렌더링 해결책으로 쓸 수 있다.
  - dgVoodoo2 기본 설정은 다중 모니터에서 보조 모니터를 전체 화면으로 잡는다. `AppControlledScreenMode=false`로 게임의 화면 모드 요청을 무시해야 창 모드가 된다.
- **상세:** [compat-survey.md](compat-survey.md) "dgVoodoo2 시험 결과"
